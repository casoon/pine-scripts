# Changelog

## v2.5.0 — 2026-07-28 (`market_tradability_engine_v2.pine`, Beta)
- Added: Boundary Quality — tracks distinct tests of each frozen balance boundary (cooldown-deduplicated, so a multi-bar press against one edge counts as one test) and the rejection quality of each test (how far price rotated back toward the range midpoint). A repeatedly tested boundary with weak rejection (or opposing acceptance pressure) is flagged as boundary stress/fatigue. New `Boundary Quality` input group (touch distance, test cooldown, fresh/stressed test thresholds, weak-rejection threshold, require-stress-for-Ready toggle, failed-breakout detection + re-entry distance)
- Added: failed-breakout / boundary-sweep detection — a wick excursion beyond an armed boundary that closes back inside the range with opposing bar acceptance resets that side's breakout-acceptance streak, is logged as a `noTradeReason`, surfaces as a dashboard action and a dedicated marker/alert, but does not clear the armed range
- Fix: Energy's momentum-acceleration component gave flat or declining acceptance magnitude a neutral 50-point contribution (via `f_scale`'s symmetric -20..20 mapping). It now measures positive acceleration only — flat/declining acceptance contributes zero. Lowers the average Energy score, so the Reactivity-preset Energy thresholds (Low/Very Low/High) were lowered as provisional starting points pending recalibration against the log
- Changed: `READY` can now optionally require repeated asymmetric boundary stress on the pressured side (`Require Boundary Stress for Ready`, off by default) in addition to compression, rising energy and directional acceptance pressure
- Changed: state machine no longer accumulates a same-target-agnostic disagreement streak. It now tracks one specific pending target state (`pendingState`/`pendingStateBars`) so alternating candidates can no longer combine into a false confirmation for an arbitrary state none of them individually supported for long enough. Current-state invalidation is now a separate check (`currentStateStillValid`/`invalidCurrentStateBars`) so a stale confirmed state can still be left even while candidates keep churning
- Calibration log: `MTE2 CONFIG` now includes the new Boundary Quality inputs; `MTE2 CAL` replaces `disagreementStreak` with `pendingState`/`pendingStateBars`/`invalidCurrentStateBars` and adds boundary test/fatigue/rejection-quality/stress and failed-breakout fields
- Data window: added Upper/Lower Boundary Tests, Upper/Lower Boundary Fatigue, Upper/Lower Rejection Quality

## v2.4.1 — 2026-07-17 (`market_tradability_engine_v2.pine`, Beta)
- Fix from first real v2.4.0 calibration export (USOIL 1D, 2,235 bars): `previousRangeHigh/Low` used `high/low[rangeLength + 1]`, which compared the active rolling range with a separate window shifted about one full Range Window into the past — not with the immediately previous rolling range as intended. Median sustained boundary stability collapsed to 0.01; all 86 range-flavored bars stayed below Structure 55, so Balance/Compression/Ready/Breakout each occurred zero times. The comparison now correctly uses `rollingRangeHigh/Low[1]`
- Range Structure now combines sustained boundary stability with range compactness through their geometric mean. Correcting the one-bar reference alone would make stability exceed 80 on most bars and let Range dominate again; compactness ensures a respected but wide directional window is not mislabeled as a compact balance. `rangeCompactness` is included in `MTE2 CAL`
- Analyzer: treat logged `NaN`/infinite numeric values as missing instead of allowing warmup values into forward-outcome calculations; optional `--tps-csv` reconstructs a matching TPS state series from its transitions and reports the barwise MTE/TPS cross-check
- Research result from the invalid v2.4.0 run: 80.9% NO_TRADE; only Trend/Exhaustion states fired. Assuming `TPS_0546e` is the matching USOIL 1D TPS export, only 19.5% of MTE Trend bars overlapped TPS Trend Healthy/Strong versus 28.5% baseline occupancy. v2.4.1 requires a fresh export before any threshold conclusions

## v2.4.0 — 2026-07-17 (`market_tradability_engine_v2.pine`, Beta)
- Fix: Range Structure no longer jumps to 100 whenever the rolling boundaries happen to remain unchanged for one bar. Boundary stability is now EMA-smoothed across the Quality Window, so `rangeFramework` requires sustained boundary persistence and no longer suppresses Trend on isolated no-new-extreme bars
- Fix: inverse baseline-cross quality now ranks `-baselineCrossRate` directly instead of calculating `100 - percentrank(crossRate)`. The old form inverted ordering but mishandled the many tied zero-cross observations: if most lookback values were zero, a current zero could still receive very low trend-cleanliness quality
- Fix: reset the disagreement streak when a state transition is accepted, preventing evidence accumulated against the previous state from leaking into the next transition
- Diagnostics: every `NO_TRADE` candidate now carries a machine-readable dominant blocker (`NO_FRAMEWORK`, `RANGE_MID_ENERGY`, `TREND_ACCEPTANCE_WEAK`, breakout/Ready blockers, etc.). The dashboard's formerly redundant Candidate row shows that blocker while no candidate qualifies, and its action distinguishes waiting for confirmation, no qualified setup despite valid structure, and genuinely weak structure
- Calibration log: `MTE2 CAL` is now a self-contained per-bar research row with timestamp/symbol, OHLC/ATR, range/trend component scores, all major state gates, armed/streak/state-duration context and the blocker reason. State values use stable underscore keys such as `NO_TRADE`; config logging now includes volume and JMA settings
- Added `scripts/analyze_mte2.py`: parses German/English TradingView Pine-log CSV exports, reports state/candidate coverage, duration, NO_TRADE blocker distribution and gate activation, computes ATR-normalized 5/10/20-bar forward outcomes, and optionally compares allowed versus blocked realized strategy signals

## v2.3.1 — 2026-07-17 (`market_tradability_engine_v2.pine`, Beta)
- Fix: the v2.3.0 trend-structure composite mixed percentrank components (average ~50 by construction: cross rarity, efficiency, ADX) with two absolute-scale components (`trendSlopeQuality`, `trendConsistencyQuality`) that average well below 50, since strong slope/consistency readings are rare. That silently pulled the composite's expected value under the Structure Threshold (55 on Balanced) regardless of instrument or timeframe — confirmed on live NatGas/WTI charts across 15m/1H/4H/1D, where Structure never cleared 55 even on a visually clean trend, so `hasFramework` stayed false and TREND/BALANCE/COMPRESSION/READY were all starved. Both components are now `ta.percentrank(...)`-normalized against `Rank Window` like the other three, matching the file's own "ranked against own recent history" design principle

## v2.3.0 — 2026-07-17 (`market_tradability_engine_v2.pine`, Beta)
- Fix: READY was logically impossible — it required `establishedCompression` (neutral acceptance, `|Acceptance| < neutral band`: 12/18/24) and directional pressure (`|Acceptance| ≥ pressure threshold`: 16/24/32) on the same bar, contradictory at every Reactivity level. Compression now arms a memory state (`compressionArmed`); READY fires when energy builds and pressure appears while that armed compression is still valid. Disarmed on breakout, when the structure flips trend-flavored, or when the balance hasn't re-confirmed within one Range Window (stale)
- Fix: breakout confirmation measured against a moving boundary — one bar after a breakout, `ta.highest(high[1], rangeLength)` already contained the first breakout bar, so multi-bar acceptance effectively demanded ever-new highs/lows plus buffer instead of "price holds outside the same range". The boundaries are now frozen (`armedRangeHigh/Low`) whenever a balance is established and the breakout is measured against those; raw breakouts additionally require an armed balance to exist. The plotted balance boundaries show the frozen reference while armed
- Changed: trend-structure quality is no longer just the baseline-cross rarity (a quiet drift sitting on one side of a slow baseline scored high) — now a composite of cross rarity (25%), efficiency-ratio rank (25%), ADX rank (20%), normalized slope (20%) and directional consistency (10%)
- Changed: dashboard Structure/Energy cells no longer use the green/amber/red good-bad scale — Structure and Energy are properties, not verdicts (high Structure in a dead downtrend is a valid No Trade; low Energy is exactly what Compression looks like). Structure: blue when above threshold, gray otherwise. Energy: orange (active) / gray (middling) / blue (quiet). Acceptance keeps its directional red/green
- Changed: action texts reworked — `BREAKOUT` said "CHECK CONFIRMATION" although the state is only reached after close-outside + buffer + acceptance bars + energy + directional acceptance all confirmed; now "CHECK RETEST / SETUP". Also `NO TRADE` → "STAND ASIDE", `BALANCE` → "TRADE EDGES ONLY", `COMPRESSION` → "WATCH BOUNDARIES", `READY` → "PREPARE FOR BREAKOUT", `TREND` → "ALLOW TREND SETUPS", `AFTERMATH` → "DON'T CHASE"
- Changed: the `STOP` marker fired on every No-Trade entry and read like an exit signal — now `PAUSE`, and only when a tradable state (Ready/Breakout/Trend) is actually left
- Changed: `recentImpulse` required the energy peak and acceptance peak inside the lookback but not on the same bar, so two unrelated events could combine into a phantom impulse — now a single bar must clear both thresholds. The impulse direction is stored and drives the Aftermath marker placement (previously `activeDirection`, which could stem from an unrelated earlier breakout/trend)
- Calibration log: `MTE2 CAL` now includes `compressionArmed` and `breakoutArmed`

## v2.2.1 — 2026-07-16 (`market_tradability_engine_v2.pine`, Beta)
- Fix: transition markers (`R`, `BREAK`, `STOP`, `AM`, `EX`) used `textcolor = color.white`. Unlike a table cell, `plotshape`'s `text` has no background fill behind it — it's drawn directly on the chart pane, so white text sat straight on TradingView's light-theme chart background and was effectively invisible (confirmed via a zoomed screenshot). ## v2.2.0 — 2026-07-16 (`market_tradability_engine_v2.pine`, Beta)
- Added: `Reactivity` preset (`Early` / `Balanced` / `Conservative` / `Custom`), independent of `Preset` (lookback lengths only) — resolves Structure Threshold, all three Energy thresholds, all four Acceptance thresholds, and Confirmation Bars / Minimum State Duration / Breakout Acceptance Bars in one dial, so states can be tuned to trigger sooner off softer evidence (`Early`) or wait for stronger sustained evidence (`Conservative`) without touching ten individual inputs by hand. `Custom` falls through to the renamed `(Custom)`-labeled individual inputs, mirroring how `Preset`'s `Custom` option already works
- Added: `Baseline Type` selector (`EMA`/`SMA`/`RMA`/`WMA`/`SuperSmoother`/`T3`/`KAMA`/`JMA Approx`, `JMA Phase`/`JMA Power` when JMA Approx is chosen) for the Quality Baseline, using this repo's 8-kernel "Advanced family" pattern (`rsi_advanced.pine`, `wavetrend_advanced_smoothing.pine`, and others) rather than the smaller 6-option EMA/RMA/SMA/WMA/HMA/JMA set — SuperSmoother/T3/KAMA are adaptive/filter-based and behave meaningfully differently from the plain MA family. Scoped to the baseline only, not every internal reference EMA
- Calibration log: `MTE2 CONFIG` now includes `reactivity` and `baselineType`

## v2.0.0 — 2026-07-16 (`market_tradability_engine_v2.pine`, Beta)
- Initial parallel research build: reduces v1's four scores (Tradability/Balance/Compression/Direction) to three fundamental properties — Structure (0-100, coherent framework), Energy (0-100, movement intensity building/fading), Acceptance (-100..100, are new prices held or rejected, and which way) — and derives all eight states from combinations of them
- New raw sensor: per-bar acceptance (does the bar close near its favorable extreme or get wicked back), smoothed and folded into Acceptance
- Reuses v1's state-machine mechanics unchanged (disagreement-streak confirmation, minimum-duration hysteresis, breakout hold, post-breakout Balance lock, breakout acceptance bars, Ready energy-building check) and v1's raw sensors (ATR, efficiency ratio, ADX/DI, candle/range/volume metrics)
- Six-row dashboard (Market State, Candidate, Structure, Energy, Acceptance, Action), down from v1's nine
- Pine-Log calibration logging with an `MTE2` event prefix (`MTE2 CONFIG` / `MTE2 CAL` / `MTE2 TRANSITION`) so it can log alongside v1's `MTE` events on the same chart for side-by-side comparison
- Not yet calibrated against real data — thresholds are carried over analogously from v1 where a direct mapping exists

## v1.2.0 — 2026-07-16
- Added: breakout acceptance — a new "Breakout Acceptance Bars" input (default 2) requires price to hold beyond the boundary for several consecutive bars before Breakout confirms, instead of a single spike candle
- Added: Ready now also requires volatility (ATR/bandwidth) to be ticking up off its recent trough ("energy building"), not just directional pressure near a boundary — pressure without energy behind it produced Ready states that just sat at the boundary without resolving
- Added: Compression score gained a coiling-energy component (shrinking candle bodies + growing wicks), reweighting the existing ATR/bandwidth/range/boundary/efficiency components to make room for it
- Calibration log: `MTE CONFIG` now includes `breakoutAcceptanceBars`; `MTE CAL` now includes `compressionEnergy`

## v1.1.0 — 2026-07-16
- Added: `AFTERMATH` state — a recent directional impulse (high direction + tradability within an "Impulse Lookback" window) has gone quiet: ADX is still elevated but the fast efficiency ratio has collapsed and volatility isn't expanding again. Sits between Ready and Compression/Balance in the state priority so a post-impulse pause is no longer forced into a generic No Trade or, worse, misread as a fresh Balance. New "Impulse Aftermath" input group, dashboard action hint, transition markers, and alert
- Added: dual-window efficiency ratio — a new "Fast Efficiency Length" (default 8 bars) reading alongside the existing Quality-Window efficiency ratio, used to tell a genuine range apart from a pause right after an impulse. Exposed in the calibration log and the data window
- Changed: all input labels, group names, dashboard text, state/direction names, plot/alert titles and messages translated from German to English, matching the rest of the repo's indicators
- Fix: `ta.sum` isn't a Pine v6 function — replaced with `math.sum` (efficiency ratio, directional consistency, baseline cross rate)
- Fix: exhaustion marker's `location` argument used a series ternary, which `plotshape` rejects — split into two fixed-location calls gated by `activeDirection`
- Fix: state-confirmation counter reset on every candidate flip, so a confirmed state (e.g. Balance) could get stuck long after every underlying score had moved on if the live candidate kept changing between different alternates. Replaced with a disagreement-streak counter that accumulates on any bar where the candidate disagrees with the confirmed state, regardless of which specific alternate it is
- Added: ADX's contribution to the Tradability score is now gated by the current efficiency ratio, so a still-elevated ADX from a finished impulse no longer props up the score once price has gone quiet
- Added: post-breakout Balance lock ("Post-Breakout Balance Lock", default 10 bars) — a tight consolidation right after a breakout no longer immediately re-qualifies as a new Balance
- Added: dashboard "Candidate" row showing the live candidate state next to the confirmed state, to surface staleness at a glance
